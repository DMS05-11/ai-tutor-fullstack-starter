# App Flow Document for AI Tutor Application

## Onboarding and Sign-In/Sign-Up
A new user arrives at the application’s landing page, which provides an overview of the AI Tutor’s features and two clear buttons labeled “Sign Up” and “Sign In.” When the user clicks “Sign Up,” they are taken to a dedicated sign-up page where they enter their name, email address, and password. Upon submission, the application calls the backend API to create a new user record with an unverified status and immediately triggers an email verification message. The user sees a confirmation message instructing them to check their inbox for a verification link. In the email, a secure link points to the app’s verification endpoint; when clicked, it opens a simple page that validates the token, marks the user as verified, and displays a success message with a button to “Proceed to Sign In.” If the token is expired or invalid, the user sees an error page with instructions to request a new link. Once the account is verified, the user returns to the sign-in page and enters their credentials. On successful login, the backend checks the password and confirmed verification status before issuing a session cookie and redirecting the user to the main courses page. A “Forgot Password?” link on the sign-in page allows users to request a password reset email. They enter their address, receive a reset link, and follow it to set a new password before returning to sign in. At any point after signing in, the user can click a “Sign Out” button in the header to clear the session and return to the landing page.

## Main Dashboard or Home Page
After signing in, the user lands on the courses dashboard, which serves as the central hub. The top of the page features a header bar displaying the application logo on the left and the user’s name with a dropdown menu on the right. The dropdown offers links to “My Profile,” “Settings,” and “Sign Out.” Below the header, the main view presents a list of available courses in a clean table format. Each row shows the course title and a brief description. A sidebar on the left gives quick navigation to “All Courses,” “Completed,” and “In Progress” sections. The page is responsive so the sidebar collapses into a menu icon on smaller screens. The user can click on any course title or a “View” button to navigate to the detailed course view.

## Detailed Feature Flows and Page Transitions
When the user selects a course from the list, the app transitions to a dynamic course page whose URL includes the course ID. On this page, the application fetches the full course content from the backend API and displays it in a reader-friendly layout, with a title at the top and rich text or multimedia content below. A “Back to Courses” link in the header returns the user to the dashboard. Within the course reader, a progress tracker at the bottom lets users mark lessons as complete. Clicking the tracker triggers an API call to update the user’s progress and updates the UI to reflect completion. If the user tries to access the course pages without logging in, the app automatically redirects them to the sign-in page. If they are logged in but have not verified their email, any attempt to reach protected routes also sends them to a page reminding them to verify their account, along with a button to resend the verification email.

## Settings and Account Management
From the header dropdown, the user can open “My Profile,” which leads to a page displaying their current name and email. A simple form there lets them change their display name or email address. After editing, they click “Save Changes,” the application calls the update API, and the page shows a confirmation message. If the email is changed, the user is prompted to verify the new address in a similar token-based flow. The “Settings” link in the same dropdown directs users to notification preferences, where they can toggle email updates for new courses or progress reminders. Upon saving, the page confirms the saved preferences. Both profile and settings pages include a link to return to the courses dashboard.

## Error States and Alternate Paths
If the user submits invalid data at sign-up or profile pages—such as an improperly formatted email or too short a password—the form displays a clear error message next to the offending field and prevents submission. During login, entering the wrong credentials shows an inline notification stating “Invalid email or password.” Attempting to log in before verifying the email shows a message prompting verification. If the user loses internet connectivity while fetching courses, a banner appears at the top of the dashboard with a “Retry” button. When a course ID in the URL does not exist, the app shows a friendly 404 page explaining the course could not be found and offers a link back to “All Courses.” If the email verification link is invalid or expired, the verification page displays an error with an option to resend the verification email.

## Conclusion and Overall App Journey
A typical user journey begins with discovering the AI Tutor on the landing page, signing up with their email and password, and confirming their address via email. After successfully verifying and logging in, they arrive on the courses dashboard, choose a course, and engage with its content. Along the way, they can update their personal details, adjust notification preferences, and track lesson progress. Error messages guide them through any hiccups, and secure session handling ensures they can sign out safely when finished. Each element of the flow works together to help learners sign up, explore, and complete courses in a smooth, intuitive experience.
